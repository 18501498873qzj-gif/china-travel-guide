4. Data Storage and Security四、数据存储与安全

We implement a minimum-data, no-persistent-storage architecture on the application level:

我们在应用层采用「最小数据 + 不落库」架构：

  • Travel preference inputs exist only in the memory of the Node.js process for the duration of that single HTTP request (typically 60–120 seconds while the guide generates). Once the guide is downloaded and/or emailed, these inputs are discarded with the request context and are not written to any database, file, or log. / 旅行偏好输入仅在单次 HTTP 请求期间存在于 Node.js 进程内存中（通常 60–120 秒，用于攻略生成）。攻略下载 / 邮件发送完成后，输入内容随请求上下文释放，不会写入任何数据库、文件或日志。
  • Email addresses are used only as the recipient parameter of a single call to transporter.sendMail() via Nodemailer. They are not saved to disk, not added to lists, and are not accessible after the request completes. / 邮箱地址仅作为当次 Nodemailer transporter.sendMail() 的收件人参数使用，不落盘、不入列表、请求结束后在后台不可访问。
  • Transport security: all connections to our Service are served over HTTPS (TLS 1.2+). API calls to DeepSeek, Feishu, and Gmail use TLS-secured endpoints with API Key / App Password authentication via environment variables on Render (never committed to source code). / 全站 HTTPS（TLS 1.2+）传输。DeepSeek、飞书、Gmail 接口均走 TLS，密钥通过 Render 环境变量注入（不写入源代码仓库）。
  • No method of transmission over the Internet is 100% secure — while we strive for best practices, we cannot guarantee absolute security. / 尽管我们采用业界最佳实践，仍无法保证互联网传输 100% 安全，您的数据传输风险自负。
